# Working on Eve

Eve is a Tauri 2 + Svelte 5 + TipTap markdown notes app (macOS and Android). README.md says what it does;
this file says how to change it without bringing back bugs it has already had.

## Checks

```bash
npm test                                       # node tests + guards + vitest (jsdom), the same as CI
npx svelte-check --tsconfig ./tsconfig.app.json
npm run verify:map                             # every sub-feature of the feature map, driven in WebKit (~3 min)
npm run e2e:selection && npm run e2e:popups && npm run e2e:code && npm run e2e:summon && npm run e2e:table && npm run e2e:handle && npm run e2e:ui && npm run e2e:head && npm run e2e:overlap && npm run e2e:forms && npm run e2e:mem   # WebKit, as CI runs them
npm run e2e:diagrams                           # Chromium (Playwright's own, or CHROMIUM_PATH=/path/to/chrome), as CI runs it; e2e:math and e2e:phone take Chromium the same way
scripts/android-unit-test.sh                   # the phone's Kotlin unit tests, as CI runs them (ANDROID_HOME with an NDK, JDK 17)
```

Do not commit `e2e/out/` screenshots that a run changed (`git checkout -- e2e/out`).

## The rules, and the guard that holds each one

Most of the ~370 fixes so far fell into a few classes. Each class now has one place it is handled and a test that
fails when something goes around it. Work through these places; if one truly can't do what you need, extend it
rather than writing a one-off beside it.

| Class of bug | Do it through | Guard |
|---|---|---|
| A note changes on save, reload, copy or paste | each node's `parseHTML`/`renderHTML`/markdown `serialize` agreeing | `src/lib/schemaGuard.dom.test.ts`: every node and mark needs a sample in `SAMPLES` (`src/lib/schemaSamples.ts`) (a new one without it fails); each sample is saved, read back, copied and pasted, alone, nested in quote/callout/toggle/list, and beside every other block |
| Text copied into another app (a chat, a mail, a terminal) is not what the note shows: `&lt;` `&amp;` `&#32;` for < & and spaces, an empty line after every line, `<>` around an address, a table's `<!-- eve:widths -->` | a node's markdown `serialize` when `state.options.copying` is set (`copySerializer` in `src/lib/editor.ts`): the one place a copy leaves out what only the file needs. Eve pastes its own copy from its HTML (`data-pm-slice`), never from that text | `src/lib/schemaGuard.dom.test.ts` ("copied as plain text", and in the nested and side-by-side cases): the copy is the note's markdown less what `forOtherApps` takes out, with lines of text a line apart at any depth; and every sample again with `PROBE` (`< > & &lt;`) after each run of text and spaces opening each line: each run is in the copy as it is, only markdown's backslash allowed among its letters. Something new that only the file needs goes in `forOtherApps` |
| An editing key breaks the note or ⌘Z can't take it back | the editor's keymaps and commands in `src/lib/editor.ts`, `blocks.ts`, `lists.ts` (a list's keys, input rules and markdown) | `src/lib/keyMatrix.*.dom.test.ts` (`keyMatrix.harness.ts`): every key in `KEYS` at both ends of every line of every block in `BLOCKS`, alone and nested — the note stays valid, saves the same twice, one ⌘Z restores it, no newline in non-code text. Add new blocks to `BLOCKS` and new editing keys to `KEYS` |
| Back / Esc / "put away" forgets a popup; a popup opens without the keyboard in it; focus lands nowhere after one closes | `ui.layers.push(...)` (`src/lib/ui.svelte.ts`): every popup, sheet, dialog, panel is a layer; a modal one names its box (`ownSelector`: the keyboard is put in it as it is drawn, if it has not taken it itself) or `letsGoOfKeyboard` (its keys claimed) — the type will not take a modal layer with neither; closing it gives focus back once | `src/lib/layers.dom.test.ts` (`OPENERS satisfies Record<LayerId, …>`: a new `LayerId` without an opener fails `svelte-check`; each one opened with a box that takes nothing has the keyboard in it); the focus sentinel (`src/lib/focusWatch.ts`, wired in `src/lib/testSetup.ts`) fails any test that leaves focus on `<body>` — use `letGo()` for a deliberate blur, `allowFocusLoss()` in a test that means it; a menu or a list takes its own Esc first (a `PRIORITY.top` claim), wherever the keyboard is — `src/lib/escFirst.dom.test.ts` |
| A dropdown opened by the pointer leaves the keyboard outside it, so ↑↓ do nothing until it is clicked into | a dropdown is `ui.openMenu(...)` (`src/Menu.svelte`) or `<Select>` (`src/Select.svelte`): both put the keyboard on the list as it opens (the current choice, or the list itself) and move it with ↑↓; its click-outside catcher is a `<Scrim>` (below) | `e2e/popups.mjs` ("every dropdown opened by the pointer"): each one clicked open in WebKit, the keyboard in it at once, two ↓ moving it to two other items. A new dropdown goes in its list. `src/lib/dropdownOnly.test.mjs` fails on a `role="listbox"`/`"menu"` or `<select>` drawn anywhere else (the typed pickers that keep the keyboard in the text are named in it with why) The pickers that come up as you type (/ [[ @ :) keep the keyboard in the text: `src/lib/pickerKeys.dom.test.ts` |
| A popup put away by a click outside it leaves its click catcher taking the next click while it fades out (a menu opened at once after another did nothing) | a click catcher (a box over the whole window that draws nothing, there to be pressed) is `<Scrim>` (`src/Scrim.svelte`): its fade is its own and plays wherever it sits (`transition:fade\|global`), and Svelte makes an element inert the moment its own outro starts, so the next press goes to what is under it | `src/lib/scrimOnly.test.mjs` fails on a catcher drawn anywhere else (an element with nothing in it under a `position: fixed; inset: 0` rule or style) and on a Scrim without a `\|global` transition of its own; `e2e/popups.mjs` ("click through"): each popup put away by a click outside it and clicked there again while its fade, drawn out, still plays, in WebKit and on a phone, the press reaches what was under it |
| A key reaches the wrong handler; IME Enter does something | `claimKeys(...)` in `src/lib/keys.ts`, the only window/document key listener; `handledBy(e)` instead of flags on events | `src/lib/keyListeners.test.mjs` fails on any other window/document/body key listener (element listeners need an allowlist entry with a reason) |
| A drag goes on after the button is let go, or sticks to the pointer after a finger is taken away (a box, a line, a selection box, a picture's width, a table's row) | `followPointer(...)` in `src/lib/followPointer.ts`: from the press it listens on the window and stops at the release or a gesture taken away (`pointercancel`); given the press, its element keeps the pointer (`setPointerCapture`) | `src/lib/pointerListeners.test.mjs` fails on a `pointermove`/`pointerup`/`pointercancel`/`mousemove`/`mouseup`/touch move or end listener on the window or the document, or a `setPointerCapture`, anywhere else (a listener on the whole app that is no gesture's, hover, is named in it with why; one on an element of a part's own is fine); `src/lib/followPointer.dom.test.ts` |
| A syllable typed through an input method (한글) comes out in jamo, goes missing or lands in front: something the app draws in the note changed while the syllable was being put together | `src/lib/ime.ts`: a node view's `update` keeps its own record of the node and draws through `whenComposed(view, draw)`; a plugin's decorations are `heldWhileComposing(...)` (held where they were until the syllable is in) or `lineAttributes(...)` (one block's attributes, which may follow each key: an empty line's hint); no widget decorations; only the input method ends a composition | `src/lib/imeWrites.test.mjs` fails on `decorations` not through the gate, a `Decoration.widget`, a node view `update` that writes or calls anything but `whenComposed`, a stock node view spread without an `update` of Eve's, and a `new CompositionEvent`; `src/lib/ime.dom.test.ts`: a syllable composed in each kind of line in `CASES` changes nothing outside its line and none of its line's decorations until it is in. New kinds of line go in `CASES` |
| A picker (`/`, `[[`, `@`, `:`) takes the Enter meant for a new line | `PICKERS` and `suggestKeys(...)` in `src/lib/slash.ts` | `src/lib/pickerKeys.dom.test.ts`: every picker in `PICKERS` × typed / arrows / Esc, with the expected outcome |
| A popup or bar is clipped, off screen, or covers text | `floatAt(...)` / `placeAt(...)` and `screenInsets()` in `src/lib/popup.ts` | `src/lib/popup.dom.test.ts` (a grid of Mac and phone windows, keyboard up); `src/lib/zIndex.test.mjs` fails on a numeric `z-index` (use the `--z-*` tokens on `:root` in `src/app.css`: their values are the order) and on `window.innerWidth/innerHeight` in components |
| The page's head (icon, Add icon / Add cover, cover, title) overlaps itself or the window's bars in one window but not another | `Editor.svelte` only: a window sets `--head-top` / `--head-side` on `.scroll`, the head reads them once; a cover's and an icon's rules sit beside them | `e2e/head.mjs`: 5 windows (Mac, tabs, sidebar closed, two phones) × icon × cover × links here × a page under another — in order, clear of the bars, in line with the title; `src/lib/zIndex.test.mjs` fails on `.page-head` / `.page-controls` styled outside `Editor.svelte` |
| Text too faint to read in one theme (a dim label, a link) | colours are `--*` tokens on `:root` in `src/app.css`, set as `light-dark()` pairs; the accent drawn as words or an icon is `--accent-text`, `--accent` is a fill | `src/lib/contrast.test.mjs`: every text token on every ground it sits on, both themes, 4.5:1 (3:1 for a label on the accent); fails on `color`/`fill`/`stroke: var(--accent)` |
| The caret jumps to another cell, item or line when the open note comes in changed (sync) | `takeBody(...)` in `src/lib/takeBody.ts`, the only place a body from outside goes into an open editor; a note read back must be the same document as the one open | `src/lib/caretSync.dom.test.ts`: every sample in `src/lib/schemaSamples.ts`, alone and nested, a caret in every line, each line before it written longer and shorter — the caret stays by its text, a picture or formula chosen whole stays chosen; `schemaGuard`'s "read back, the same document" (a blank line or a board read back differently is taken for an edit) |
| Opening a note or typing slows down as the library grows | the stores' lists are `$derived` and kept (`notes.visible`, `pages`, `daily`, `byTitle`), typed `readonly` so nothing sorts them in place; nothing adds or removes a stylesheet when a note opens | `src/lib/speed.dom.test.ts`; `npm run e2e:perf` times a start, a key and a switch with 800 notes in WebKit (judge by a built app: `EVE_URL` on `npx vite preview`) |
| The app holds more and more memory as it is used (seen in gigabytes) | lists and caches kept bounded; what a closed panel or a note left behind drew is let go | `e2e/mem.mjs`: 80 notes, a long one, diagrams and formulas, opened and typed into round after round — fails over a budget or when the later rounds climb over the second; a Mac app writes `memory.log` (`src-tauri/src/mem.rs`: the page's footprint a minute, with what was done before it — notes, panels, syncs) to find what a climb followed |
| A note written on two devices before they sync loses one device's words | `src/lib/sync.svelte.ts`: a note changed on both sides since they last agreed is put together line by line (`merge3`, from the version they agreed on, `Repo.blob`); what cannot be is kept as a conflict copy, never dropped; a rename on the other device is followed here once the pull is in | `src/lib/syncConflict.dom.test.ts` (this app's sync against an in-memory GitHub, `fakeGitHub.mjs`, the other device a `Repo` of its own); `src/lib/merge3.test.mjs` |
| Something Notion's editor does (a key at a line's edge, a markdown shortcut, a / item, an @ day) Eve does not, found by a user one at a time | the keymaps and commands above, the / menu's `SLASH`, `dayChoices` | `src/lib/notionParity.dom.test.ts`: one case per behaviour of notion.com/help/keyboard-shortcuts and /writing-and-editing-basics, and the keys they leave unsaid; what Eve leaves out on purpose is named at its top. | A flowchart's steps all moved when one line was drawn in | a flowchart without lanes is drawn by `laneSvg` too (`charts.ts`, unless it has what only mermaid draws): each step across from the one its first line in comes from, a column's steps side by side as near their places as they fit (`place` in `src/lib/lanes.ts`) | `src/lib/diagramGuard.dom.test.ts`: a line that pushes no step on moves none; one that does moves that step and what follows it |

| A screen changed that no agent can prove in the running app (only tests saw it) | a feature file in `.claude/skills/verify-eve/features/`, driven with drive.mjs, its steps the ones that worked; each sub-feature checked in `.claude/skills/verify-eve/drives/<feature>.mjs` by `t.ok('<id>', …)` (`npm run verify:map`, in CI) | `src/lib/featureMap.test.mjs`: every `.svelte` file listed under `## Screens` in that folder's README, each linked to a feature file with the four sections; every sub-feature has a `t.ok` in a drive, a test titled `'<id>: …'`, or **Unchecked:** and why in its line; a new screen or sub-feature without one fails `npm test` |

A bug fix starts with a failing case in the guard for its class (or in the nearest `*.dom.test.ts`), then the fix.

## Conventions

- No comments for what the code says or for how a bug went: names, types and tests say it. A comment stays only for what something outside forces (WebKit, ProseMirror, mermaid, a platform or a format) and the code alone cannot show.
- Commits and PRs describe user-visible behaviour.
- Versions live in `src-tauri/tauri.conf.json`, `src-tauri/tauri.android.conf.json` (the phone's own), `src-tauri/Cargo.toml`
  and the `eve` entry in `src-tauri/Cargo.lock`; releases are built by `.github/workflows/release.yml` from a `v*` or
  `android-v*` tag.
